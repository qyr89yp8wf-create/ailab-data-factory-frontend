## F01：图像生成模型配置类型不一致

**前置数据**：物流运单图像数据集 `DATASET-20260812-0001`，版本 `F3454CDA3969`。

**复现步骤**：

1. 任务中心→文档图像→新建任务→定向扩增。
2. 选择上述数据集与版本。
3. 开启“自定义扩增设置”。
4. 查看首组“图像生成模型”，打开其下拉列表。
5. 新增第二组，对比默认模型。

**实际结果**：首组默认 `Qwen3-14B`；候选包含 `Qwen3-14B`、`Qwen3-VL-8B-Instruct`、`Doubao-Seedream-4.0`、`DeepSeek-V3.1`。首组默认值与页面主图像模型 `Doubao-Seedream-4.0` 不一致，未按图像生成能力限制。新增组的代码默认值则为 `Doubao-Seedream-4.0`，形成首组与新增组默认行为差异。

**预期结果**：图像生成字段提供具备对应能力的模型，首组与新增组遵守相同的默认策略；如果某字段实际用于文本指令生成，应使用与实际用途一致的标签。

**证据摘录**：

```text
customExpansionSettings_0_model
* 图像生成模型
(selected) Qwen3-14B
Qwen3-VL-8B-Instruct
Doubao-Seedream-4.0
DeepSeek-V3.1
```

**定位线索**：`src/main.jsx:1394` 组内Select使用混合静态列表；`src/main.jsx:1463` 首组初值固定为Qwen3-14B。V4存在相同配置逻辑。

**影响与边界**：用户可能提交语义不正确的模型配置。因本轮使用Mock，尚未证明真实服务请求会如何失败；P1为配置准入风险建议级别。

**建议**：以模型能力过滤候选，首组使用与新增组相同的模态默认值，并在提交时校验模型能力，而不只是必填校验。

**复测标准**：文档首组与新增组默认一致；下拉不允许不具备图像生成能力的模型；对话/时序仍保留各自适用模型。

## F02：来源数量变化未同步默认增强目标

**前置数据**：物流客服多轮对话 `DATASET-20260812-0003`，版本 `F232BC2AC51C`，98条。

**复现步骤**：

1. 对话文本→新建数据增强任务。
2. 选择上述数据集与版本。
3. 不点击目标数量，直接观察“目标增强样本数”。
4. 点击该输入框，再点击任务名称使其失焦。

**实际结果**：初始显示100，控件上限是98。只有执行第4步后才变成98。重新进入流程可复现。

**只读DOM证据**：

```json
{"value":"100","max":"98"}
```

聚焦再失焦后：

```json
{"value":"98","max":"98"}
```

**预期结果**：来源选定后立即初始化合法目标，不依赖用户触碰输入框纠正默认值。

**定位线索**：`src/main.jsx:1463` 的 `targetCount:100`；来源联动和InputNumber上限应共同约束初值。V4也有相同默认值。

**影响与边界**：初始表单呈现越界值，可能造成预期数量与实际处理数量不一致。本轮未将越界默认配置提交到真实模型，不能宣称产生了超量数据。

**建议**：在选择版本后将默认值限制为当前可选数量；切换到更小来源时同步修正；为自动调整提供简洁说明。

**复测标准**：来源98条时初值≤98；来源1条时初值≤1；切换来源后不残留上一来源的越界目标；无需额外聚焦失焦。

## F03：已发布时序模板使用草稿状态标题

**前置模板**：`COLDTPL-REEFER-MODEL-DEMO-V2`，列表显示“已发布”。

**复现步骤**：

1. 模板中心找到“冷藏集装箱多变量时序示例（演示用）”。
2. 确认列表状态为已发布，点击详情。
3. 查看顶部状态和ID，再切换任意步骤。

**实际结果**：详情顶部显示“草稿已保存”“草稿 ID：”，ID为空。各步骤仍可读，字段保持只读。

**预期结果**：显示真实“已发布”状态及模板ID/版本；只有草稿显示草稿保存状态。

**证据摘录**：

```text
列表：COLDTPL-REEFER-MODEL-DEMO-V2 / 已发布
详情：草稿已保存
详情：草稿 ID：
```

**定位线索**：`src/ColdChainTemplateCenter.jsx:628` 无条件渲染草稿标签和 `draft.draft_id`；同一实现也存在于V4。

**影响**：用户无法从详情准确判断模板生命周期和身份，但本轮未发现只读权限被突破。

**建议**：按详情类型、发布状态分别显示模板ID与草稿ID，避免把草稿操作状态复用于发布详情。

**复测标准**：已发布模板详情显示已发布和非空模板ID；草稿详情仍显示真实草稿保存状态及草稿ID。

## F04：总体分数与现有验收文档冲突

**复现步骤**：

1. 数据中心→物流运单图像数据集→版本 `A15343CDB3D4`→质检报告。
2. 查看“整体质检结果”。
3. 对照 `docs/质检改造验收清单.md` 第一节。

**实际结果**：页面显示“整体分数94.7分”，解释为75条可计分规则通过率的等权平均。验收文档明确写“不计算样本综合分、数据集总分或总体合格结论”。

**判断**：这是可确认的文档/实现不一致，尚不能确认哪方是最新正确业务要求。逐规则通过率本轮核对正确；不能将此问题描述成计分算法算错。

**定位线索**：`src/RuleQualityReport.jsx:38`；V4也展示该整体分数。

**建议**：产品确认唯一口径并同步文档与UI。如果整体分数是之后批准的需求，应更新旧验收文档而不是擅自删除功能；否则按已确认要求调整呈现。

**复测标准**：需求、页面、报告JSON对整体指标的定义一致，逐规则结果与六种状态不受影响。

## 阻塞项目

### B01：三类下载缺少完成证据

涉及：D10版本下载、Q07报告下载、T18日志下载。

均已点击实际入口。报告下载额外等待8秒，浏览器工具未捕获download事件；页面无明确完成反馈。当前无法区分内置浏览器下载通道限制、工具事件不可观测与产品未完成下载，故记阻塞，不直接记下载故障。

**补验方式**：在常用Chrome/Edge使用同一入口，确认下载目录中新文件、名称、扩展名、非空内容，并核对报告/任务ID；对版本包核对ZIP清单与业务约定。发现实际无文件后再转为缺陷。

三种上传示例ZIP均有“开始下载”页面反馈，用例U04只验证该反馈，不能据此证明报告/日志下载也成功。

涉及：X01。当前原型采用Mock，没有本轮可用的真实模型端到端验收环境。真实请求、限流、鉴权、计费、真实输出质量均不属于本轮通过项。

### B03：最终删除与真实凭据操作

涉及：X02。没有执行永久删除或真实密钥保存；测试期间仅操作未保存的空表单行及取消弹窗。后续需在明确可清理的隔离测试环境和授权下执行。
