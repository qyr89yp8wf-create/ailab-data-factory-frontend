# 质检改造验收清单

改造日期：2026-09-16。

范围：Data_Factory_User_Frontend_v4，未修改管理员原型及旧用户原型目录。

## 一、统一口径

- 模板定义启用的规则全集、检查对象和判定条件。任务不再选择规则、字段，不再设置通过阈值。
- 任务提交时保存模板版本和规则快照；历史报告不随模板修改而变化。
- 每个“样本 × 规则”：通过记 1，不通过记 0；无法判定、不适用、未抽中、未执行不计分。
- 规则通过率＝通过数÷（通过数＋不通过数）。分母为零显示“—”。
- 一条规则检查多个对象时：任一不通过则为 0；全部适用对象通过才为 1；没有失败但存在无法判定对象，不记分。
- 不计算样本综合分或总体合格结论。保留现有整体指标：对计分规则的通过率等权平均；任一计分规则无有效判定时不可计算。整体指标不能替代逐规则结果，执行完成不等于质检通过。此处按 V5 UED 设计与已有计算测试同步旧清单，未新增评分算法。
- 标签分类、无判定标准的统计项单独展示，不参与通过率。
- 多次质检保存到同一个数据集版本，新增报告，不新增数据版本。

## 二、改动页面与验收方式

| 入口 | 改动 | 验收重点 |
| --- | --- | --- |
| 三类任务中心 → 新建质检任务 | 保留数据集、版本、全量/抽样、执行模型；规则和模板信息只读 | 找不到规则勾选、字段子集、任务通过阈值；规则来自模板快照 |
| 任务详情 → 质检报告 | 新增统一逐规则报告 | 显示规则通过率及六种状态数量；执行异常不能变成通过 |
| 数据中心 → 版本详情 → 质检报告 | 使用相同报告组件，支持报告历史切换 | 同版本可以有多份报告；切换报告后范围、计数、明细随之切换 |
| 数据中心 → 版本详情 → 数据预览 | 增加报告选择和样本逐规则结果 | 保留原图像/对话/时序预览；不再显示样本综合分或总体 PASS |
| 报告 → 数量/规则名 | 打开样本明细抽屉 | 可切换通过、不通过、无法判定、不适用、未抽中、未执行；能看到样本 ID、位置和原因 |
| 三类模板 → 试运行 | 使用统一逐规则报告，保留生成产物和参数配置 | 报告对应试运行时模板启用规则；修改配置后需要重新试运行 |
| 运单、合同等文档编辑入口 | 补齐示例编辑入口与逐规则试运行展示 | 运单切页不白屏；取消基础规则后，报告不再出现该规则；合同不再展示固定的全通过卡片 |
| 数据增强任务 | 依据一条报告规则的“不通过/无法判定”结果选样 | 可选数量来自该规则；目标数量不能超过可选数量；生成样本关联到所选来源样本 |
| 定向扩增任务 | 从规则不通过数量、已有标签缺口或自定义目标确定新增数量 | 不设置目标分数；执行错误不当作低质量缺口 |
| 报告下载、数据集版本下载 | 报告 JSON 与逐样本 JSONL 使用同一结果口径 | 每任务独立结果文件；未检样本不记分；原有示例文件保留 |
| 历史报告入口 | 明确提示缺少新版逐规则结果 | 不根据历史平均分捏造规则明细；可重新发起质检 |
| 终止质检任务 | 保存已执行部分的报告 | 已处理样本保留结果，剩余样本显示未执行；不生成新数据版本 |

## 五、原型边界

当前仍为前端 Mock，不调用真实 Dingo 或模型服务。通过/不通过及错误数据用于验收流程与交互，不代表真实检测准确性。

数据集下载继续使用此前约定的固定示例包，并附加当前版本的模拟报告；固定示例样本不是动态任务实际生成的完整数据，不能据此验收真实交付包的样本关联。

旧报告缺少原子结果，不进行自动回填；需要新建质检任务生成新版报告。
