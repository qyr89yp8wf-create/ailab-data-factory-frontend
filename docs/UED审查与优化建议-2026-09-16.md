# 数据生成工具：UED 审查与优化建议

日期：2026-09-16  
对象：http://127.0.0.1:8768/ 的当前运行原型  
方法：浏览器实际点击、滚动、条件表单展开、页面截图观察、异常控制台核对，以及用户提供的两张截图。属于专家认知走查，不是真实用户招募实验。  
配套方案：[UED设计与Design-Tokens-2026-09-16.md](./UED设计与Design-Tokens-2026-09-16.md)

## 1. 结论

当前主要问题是信息架构、容器和信息权重失控。继续逐块添加 Card、Alert、Drawer，会使功能越完整，页面越难用。应先重排页面，再统一视觉样式。

优先处理五件事：

1. **数据集、版本、报告进入主页面；样本检查最多保留一层侧栏。**
2. **任务表单固定标题和操作，不固定任务名称/描述表单。**
3. **右侧任务依据只放摘要，完整规则和报告移到独立页面。**
4. **普通解释改为字段帮助或折叠说明；有风险且需要行动时才用 Alert。**
5. **先修复对话模板规则展开导致的整页空白，再验收视觉改版。**

本轮没有修改应用代码、保存业务配置或提交任务。以下建议为待实施设计，不是已修复声明。

### 2.2 如何理解“全站点击”

本轮覆盖所有侧栏页面、12 个任务创建入口和三类模板代表性详情，但**不是全站全部控件、全部动态数据、全部条件分支的穷尽测试**。表中未覆盖项仍应在改版后的验收中补齐。不能据此宣布上传、发布、下载、真实模型调用或后端业务流程通过。

浏览器默认桌面视口约 1265×712～1280×720。未完成 1440/1920、200% 缩放或键盘全流程验证。运行中的原型内容曾变化，例如对话合成默认模板与采样表发生更新，记录以当时可见状态为准，不将自动化定位失败认定为产品缺陷。

## 3. P1：优先修复

本报告 P1 指主流程受阻、关键内容被遮挡或明显增加操作迷失；P2 指效率与理解问题；P3 指局部一致性和精修。视觉严重程度不等同于后端事故级别。

### UED-01 · P1 · 数据集链路叠加三层抽屉

- 路径：数据中心 → 物流运单图像数据集 → A15343CDB3D4 详情 → 质检报告 → 输出内容结构检查 → 不通过 23 条。
- 观察：数据集、版本、样本明细同时占据不同宽度的抽屉，多层遮罩压暗背景；多个关闭按钮分散在水平方向。与用户截图 1 一致。
- 影响：主要信息区域逐层变窄，用户难以判断返回对象、当前上下文和关闭结果。
- 方案：数据集与版本进入主页面；报告作为版本页签；点击规则进入页内钻取；只有具体样本用一层侧栏。侧栏内切换对象，不继续压入抽屉。
- 验收：上述路径同时只存在一层遮罩、一个关闭入口；返回保留版本、筛选、页码与滚动位置。

### UED-02 · P1 · 任务名称表单吸顶遮挡配置，提交操作滚出视口

- 路径：新建文档质检 → 选择物流运单及 F3454CDA3969 → 向下滚动；文档定向扩增展开自定义设置亦复现。
- 观察：名称/描述整张卡固定在内容上方，正文配置从其背后经过；真正的标题与提交操作已滚出。扩增截图中，固定块遮住目标表格上部。
- 影响：用户读配置时不断被无关字段占据高度，难以定位当前字段和完成操作。
- 方案：只固定 56px 的任务标题/保存草稿/提交栏；名称与描述随正文滚动。正文设置准确顶部偏移，错误定位也遵循该偏移。
- 验收：顶部、中部、末尾均能看到主操作；任何字段、标题、校验信息都不被固定栏盖住。

### UED-03 · P1 · 主表单被完整报告挤压

- 路径：文档/对话/时序增强选择输入版本；文档定向扩增开启自定义设置。
- 观察：右侧“任务依据”塞入完整统计卡、公式说明、元数据和多列表格，并独立滚动。文档扩增左侧四列字段中“目标数量”折成两行，右侧指标单位被挤开。
- 影响：真正需要填写的内容反而最窄；两个滚动区和横向滚动增加操作负担。
- 方案：默认单列配置；宽屏可展示 280px 摘要栏，但只保留来源版本、检查范围、相关问题数量与“查看完整报告”。自定义组最多两列；长文本独占一行。
- 验收：1280 宽度无表单横向滚动；不出现四个窄字段挤在一行；完整报告拥有主内容宽度。

### FUNC-01 · P1 · 对话模板规则展开导致整页空白

- 路径：模板中心 → 物流智能客服对话模板（演示用），草稿 `CONVDRAFT-20260916-723349` → 详情 → 质检规则配置 → 第一条基础规则的展开按钮。
- 观察：页面变为空白，导航一并消失。刷新后恢复。
- 控制台证据：`TypeError: Cannot read properties of undefined (reading 'rule_id')`，位于 `ConversationTemplateCenter.jsx` 的 `expandedRowRender` 内的 `Array.filter`。
- 处理：研发检查展开记录和规则映射中的缺失数据，补充局部错误边界；没有规则详情时显示该行的可恢复提示，不能让整站卸载。报错堆栈是定位线索，本轮未检查根因或修复代码。
- 验收：对话模板详情规则展开/收起正常；缺失映射数据也仅影响当前行；页面导航始终可用。

| UED-08 | 源任务“运行日志”“配置快照”默认直接输出大段 JSON | 日志默认时间、阶段、结果、简述；JSON 放“原始数据”；配置先摘要与差异，再原始快照 |

| UED-10 | 模板详情和任务输出使用大量灰色禁用输入框；对话生成空间“查看”也被禁用 | 只读改为正常对比度文本；查看、复制、展开在只读模式依然可用；仅数据修改动作禁用或隐藏 |
| UED-11 | 数据中心每行直接出现红色删除；任务列表反复显示禁用编辑/发布；模板列表同样如此 | 每行最多一个主要入口和“更多”；根据状态提供适用动作，危险操作放菜单底部 |
| UED-12 | 文档模板画布随整页滚动离开视野，中央留下大空白，字段列表与属性仍继续延伸 | 编辑器使用固定工作区：字段列表、画布、属性；工具栏常驻；画布独立平移缩放，页面不把画布卷走 |
| UED-13 | 对话合成事件采样将所有维度、条件和比例平铺为长表 | 按维度分组，每组显示合计；条件使用简述+展开；明确条件分母，不能把条件占比当作全量占比 |
| UED-14 | 质检分数、覆盖率、隐私问题并列；公式说明比行动入口醒目 | 摘要先告诉用户检查范围、是否完成、需处理的问题，再展示指标；“为什么这样计算”按需展开 |
| UED-15 | 文档模板详情仍出现可操作的试运行/模型控件；对话和时序详情则大量禁用 | 三模态统一查看与编辑模式；详情允许阅读操作，编辑/运行必须明确进入对应模式。当前是否会持久化未测试 |
| UED-16 | 时序合成默认模板输出字段显示“-”，事件采样为空表，同时出现“各维度比例配置完整” | 无采样维度时明确“不需要配置采样比例”；缺必需输出字段则显示阻断原因；不能以空集合呈现完成感。是否影响提交需研发复核 |

## 5. P3：一致性与细节

- **术语**：统一“文档图像 / 对话文本 / 时序数据”；“文档类图像”“对话类数据”等不再混用。“Badcase”对用户显示“异常样本”，技术名可放帮助。
- **ID 展示**：版本以描述+生成时间为主，ID 为辅助，不要求用户记住哈希。
- **计数单位**：时序模板试运行当前使用“票”，建议统一“条序列”；文档“张”、对话“条对话”，在规模字段第一次出现时解释口径。
- **状态**：未执行、运行中、无法判定、不适用不能共用“暂无数据”或一片破折号。色彩之外保留明确文字。
- **首页**：四张同权入口卡可改为“继续草稿/近期任务/需处理异常”，次级导航入口收紧；这是工作台方向建议，未做真实用户偏好测试。
- **API 列表**：当前只有名称、描述、操作，缺少判断可用性的上下文。建议补服务商、已配置模型数量与明确的验证状态；原型不得凭空显示“连接正常”。
- **模板新建菜单**：描述仍提到状态机、白名单引擎，实际详情强调事件采样/两阶段生成；菜单文案应匹配当前流程。
- **开发说明外露**：如“本地编译器”“规则清单依据02”“仍异常记录Badcase”应进入技术详情，不在普通用户配置主线占位。

## 6. 提示文案改写示例

| 当前表达 | 推荐呈现 |
|---|---|
| 蓝色块：请选择本次任务的输入数据集和确定版本…… | 区块标题“输入数据”；版本字段帮助“仅显示已完成质检的版本。” |
| 绿色块：增强和自动复检完成后只创建1个增强版本…… | 输出区普通文本“完成后生成 1 个新版本，包含增强样本与复检结果。” |
| 蓝色块：通过记1、不通过记0；大量计分说明 | 指标旁“计算方式”链接；打开后展示规则与分母 |
| 灰色大块：开启后以JSON形式覆盖模板试运行参数 | 可折叠“高级模型参数”；展开后才出现编辑器和示例 |
| 质检报告发现84条隐私命中 | 处理方式上方“报告记录 84 条隐私命中结果，请确认处理方式。”应说明是结果条数还是去重样本数 |
| API异常最多调用3次，仍异常则记录Badcase | 高级运行策略中“失败最多重试 3 次；仍失败的记录进入异常样本。” |

## 7. 建议实施顺序

### 第一批：恢复可用性

- 修复 FUNC-01；增加局部错误恢复。
- 移除名称表单吸顶，固定紧凑操作栏。
- 消除详情多层抽屉。
- 缩减任务依据，1280 宽度采用单列。

### 第二批：统一基础组件

- 引入配套设计文档的语义 tokens。
- 统一 PageHeader、Section、ContextSummary、Status、Table、FieldHelp、EmptyState。
- 清理重复 Alert、Card、禁用按钮和单页分页。
- 统一任务表单公共结构，保留三模态必要差异。

### 第三批：专业工作区

- 独立报告工作区、异常样本证据视图、可读日志。
- 模板编辑器、只读详情与试运行结果重排。
- 数据预览按模态优化；首页与API页精修。

## 8. 后续验收必须补齐的点击清单

- 三模态所有新建表单：有效输入、空输入、无可用版本、切换来源后的依赖清理、条件开关、增删自定义组、保存草稿、恢复、提交错误定位。
- 数据中心：各模态预览、版本分页、上传进度/失败/重试、下载产物、删除确认及取消。
- 任务：草稿/排队/运行/完成/失败/终止状态的详情、可用操作、报告和异常样本。
- 模板：新建、编辑、只读、各步骤、每种高级配置、画布操作、规则展开、试运行、发布确认及取消。
- API：空输入校验、服务商切换、模型增删、编辑取消、保存反馈；使用隔离测试凭据验证真实连接。
- 导航：浏览器返回、刷新恢复、关闭侧栏焦点返回、未保存离开、搜索与页码保留。
- 显示：1280×720、1440×900、1920×1080、200% 缩放；键盘完成筛选、表单和侧栏操作。
